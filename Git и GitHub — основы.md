# Git и GitHub — основы

Git и GitHub — не одно и то же:

- **Git** хранит историю изменений проекта на компьютере.
- **GitHub** хранит копию проекта в интернете и помогает работать над ним вместе с другими.

## Основные слова

- **Репозиторий** — папка проекта, историю которой отслеживает Git.
- **Коммит** — сохранённый набор изменений с коротким описанием.
- **Ветка** — отдельная линия изменений. Главная ветка часто называется `main`.
- **Удалённый репозиторий** — копия проекта на GitHub. Обычно её называют `origin`.

## Как отправить проект на GitHub

Сначала на GitHub создают пустой репозиторий. Потом в папке проекта выполняют команды:

```bash
git init
git add .
git commit -m "Первый коммит"
git branch -M main
git remote add origin https://github.com/ИМЯ/НАЗВАНИЕ.git
git push -u origin main
```

- `git init` включает Git в папке.
- `git add .` добавляет текущие изменения в будущий коммит.
- `git commit -m "..."` сохраняет их в истории.
- `git branch -M main` переименовывает текущую ветку в `main`.
- `git remote add origin ...` запоминает адрес репозитория на GitHub.
- `git push -u origin main` отправляет ветку на GitHub.

Перед `git add .` проверь, что в проект не попадут пароли, ключи и большие ненужные файлы. Для этого используют `.gitignore`.

Пример `.gitignore` для Python:

```gitignore
__pycache__/
.venv/
.env
*.pyc
```

## Обычная работа

После изменения файлов:

```bash
git status
git add имя_файла.py
git commit -m "Добавил обработчик пользователей"
git push
```

- `git status` показывает, что изменилось.
- `git add` выбирает изменения для коммита.
- `git commit` сохраняет их локально.
- `git push` отправляет новые коммиты на GitHub.

Чтобы скачать проект впервые:

```bash
git clone https://github.com/ИМЯ/НАЗВАНИЕ.git
```

Чтобы получить изменения, которые уже отправили на GitHub:

```bash
git pull
```

Обычно `git pull` получает новые коммиты и объединяет их с текущей веткой.

## Ветки

Ветки позволяют делать отдельную функцию, не меняя сразу главную ветку:

```bash
git switch -c add-login
```

После работы изменения сохраняют и отправляют:

```bash
git add .
git commit -m "Добавил вход"
git push -u origin add-login
```

На GitHub из этой ветки можно создать **Pull Request** — запрос на проверку и объединение изменений в `main`.

## Конфликт изменений

Конфликт бывает, если две ветки изменили одно и то же место в файле. Git не знает, какой вариант оставить. Нужно открыть файл, выбрать или объединить нужные части, сохранить файл и создать новый коммит.

## Коротко

Изменил файл → `git add` → `git commit` → `git push`. Git хранит историю у тебя на компьютере, GitHub — удалённую копию этой истории.
