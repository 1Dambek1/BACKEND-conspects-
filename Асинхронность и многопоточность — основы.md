# Асинхронность и многопоточность — основы

Обе техники помогают программе работать с несколькими задачами, пока часть из них ждёт. Например, сервер может одновременно обслуживать запросы пользователей.

## Пример с рестораном

Представь ресторан быстрого питания:

- Гости делают заказы.
- Кассир принимает заказ, отправляет его на кухню и ждёт, пока его приготовят.
- Повара готовят еду.

Пока первый заказ готовится, кассир может принять следующий. Это похоже на **асинхронность**: один исполнитель переключается между задачами, когда одна из них ждёт.

Если в ресторане несколько кассиров и несколько поваров, они могут выполнять разные задачи одновременно. Это похоже на **многопоточность**.

Пример — только аналогия: в программе асинхронные задачи и потоки устроены иначе, чем сотрудники ресторана.

## Асинхронность в Python

Асинхронность часто используют, когда программа много ждёт: ответ сайта, базу данных, файл или другой сервис. `asyncio` переключает задачи в моменты `await`.

```python
import asyncio


async def prepare_order(number: int):
    print(f"Заказ {number}: отправили на кухню")
    await asyncio.sleep(2)  # изображаем ожидание приготовления
    print(f"Заказ {number}: готов")


async def main():
    await asyncio.gather(
        prepare_order(1),
        prepare_order(2),
        prepare_order(3),
    )


asyncio.run(main())
```

Все три заказа ожидают приготовление одновременно. Пример закончится примерно за 2 секунды, а не за 6, потому что `asyncio.sleep()` не блокирует остальные задачи.

- `async def` объявляет асинхронную функцию.
- `await` приостанавливает текущую задачу, пока она ждёт результат.
- `asyncio.gather()` запускает несколько операций вместе и ждёт их завершения.
- `asyncio.run()` запускает асинхронную функцию `main()`.

Важно: `time.sleep()` внутри `async def` остановит весь event loop. Для ожидания в таком примере нужен `await asyncio.sleep()`.

## Многопоточность в Python

Поток — отдельная последовательность выполнения внутри процесса. Потоки полезны, когда несколько задач ждут ввод-вывод: например, сетевые ответы или файлы.

Для простого пула потоков можно использовать `ThreadPoolExecutor`:

```python
from concurrent.futures import ThreadPoolExecutor
import time


def prepare_order(number: int):
    print(f"Заказ {number}: отправили на кухню")
    time.sleep(2)  # изображаем ожидание
    return f"Заказ {number}: готов"


with ThreadPoolExecutor(max_workers=3) as cooks:
    results = cooks.map(prepare_order, [1, 2, 3])
    for result in results:
        print(result)
```

Пул создаёт до трёх рабочих потоков. Они ждут завершения своих задач одновременно, поэтому пример занимает примерно 2 секунды.

## В чём разница

| Асинхронность | Потоки |
| --- | --- |
| Обычно один поток переключается между задачами | Несколько потоков выполняют функции внутри одного процесса |
| Переключение происходит в `await` | Переключением потоков управляет операционная система |
| Хорошо подходит для большого числа сетевых запросов и другого ожидания | Удобна для блокирующих библиотек и операций ввода-вывода |
| Большую часть кода нужно писать с поддержкой `async` | Можно запускать обычные синхронные функции |

И то и другое помогает перекрывать время ожидания. **Параллельное выполнение** — это когда вычисления действительно идут одновременно на разных ядрах. Асинхронность сама по себе не означает параллельные вычисления.

## А если задача считает?

Например, программа долго перемножает большие числа. Это вычислительная задача, а не ожидание. `asyncio` не поможет: пока функция считает без `await`, она занимает event loop.

В обычной сборке CPython потоки полезны прежде всего для ожидания ввода-вывода. Для тяжёлых вычислений обычно смотрят в сторону `multiprocessing` или `ProcessPoolExecutor`, которые запускают отдельные процессы.

## Что выбрать для backend

- Много запросов к API или асинхронной базе данных — обычно `async`/`await`.
- Блокирующая библиотека, которую нужно вызвать параллельно с другими ожиданиями, — можно использовать пул потоков.
- Тяжёлые вычисления — процессы или специализированные библиотеки.

Не смешивай синхронные блокирующие вызовы с асинхронным кодом без необходимости: один такой вызов может задержать остальные задачи.

## Коротко

Асинхронность — как один кассир, который принимает следующий заказ, пока предыдущий ждёт кухню. Потоки — как несколько кассиров или поваров, у каждого своя задача. Для ожидания часто подходят оба способа; для тяжёлых вычислений обычно нужны процессы.
